# SceneSteward Runbook 05: Secret Management & Rotation

**Document ID:** `RB-05-SECRET-MANAGEMENT`  
**Target Environment:** Staging, Production  
**Audience:** Security Engineers, System Administrators  

---

## 1. Secrets Inventory
SceneSteward manages four primary classes of cryptographic secrets:
1. **Database Identity Secret (`DATABASE_IDENTITY_SECRET`)**: Shared between FastAPI backend and PostgreSQL `private.app_secrets`. Verifies that session connection context (`app.user_id`, `app.system`) was generated by the trusted application and not injected by an attacker.
2. **PII Application Encryption Key (`APP_ENCRYPTION_KEY` & `APP_ENCRYPTION_KEYS`)**: Fernet 256-bit AES-CBC symmetric keys protecting participant contact details at rest.
3. **Database Passwords (`POSTGRES_PASSWORD`)**: Passwords for `scenesteward_prod`, `scenesteward_app`, `scenesteward_readonly`.
4. **Integration Keys**: Supabase Service Role Key, Anthropic API Key, Switch Agent API Key.

---

## 2. Rotating `DATABASE_IDENTITY_SECRET` (Zero Downtime)

### Step 1: Generate New Trust Secret
```bash
NEW_SECRET=$(openssl rand -hex 32)
```

### Step 2: Inject Dual-Acceptance in Database
Using `backend/scripts/rotate_identity_secret.py`:
```bash
python -m scripts.rotate_identity_secret --new-secret "$NEW_SECRET" --phase prepare
```
This updates `private.app_secrets` to accept both the previous and new HMAC signatures.

### Step 3: Update Application Environment
Update `DATABASE_IDENTITY_SECRET` in `.env.production` and restart the API containers. The API will now issue tokens signed with the new secret.

### Step 4: Finalize Secret Rotation
```bash
python -m scripts.rotate_identity_secret --new-secret "$NEW_SECRET" --phase commit
```
This purges the old secret from PostgreSQL `private.app_secrets`.

## 3. Rotating PII Encryption Key (`APP_ENCRYPTION_KEY`)

SceneSteward supports key rings for zero-downtime field re-encryption:

### Step 1: Generate New Key
```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

### Step 2: Update Key Ring Configuration
Set `APP_ENCRYPTION_CURRENT_KID` to the new key ID (`prod-2026-v2`) and keep the old key in `APP_ENCRYPTION_KEYS`:
```bash
APP_ENCRYPTION_CURRENT_KID=prod-2026-v2
APP_ENCRYPTION_KEYS='{"prod-2026-v1": "OLD_KEY", "prod-2026-v2": "NEW_KEY"}'
```
All new writes will use `prod-2026-v2`. Existing records encrypted under `prod-2026-v1` will continue to decrypt seamlessly.

### Step 3: Re-encrypt Existing Records
Run the key rotation batch re-encryption script:
```bash
python -m scripts.rotate_encryption_keys
```
Once re-encryption is complete, the old key can be safely deprecated.
